Tabimate — project brief
What it is

Tabimate (旅 tabi = journey + mate) is a daily browser trivia game about animals. Everyone gets the same prompts each day (e.g. "Name an animal that lays eggs"). The player types an animal; each accepted answer has a hand-set level (1–5, 0 for no match). Each matched animal joins a trail of followers behind the player. Each answer moves the player forward by its level; crossing score thresholds enters new biomes (Town → Grassland → Forest → …). The run ends with a shareable team card. Original art and naming only: no Pokémon names, sprites or UI.

Rules of the game
Daily reset at 12:00 (noon) Asia/Singapore (RESET_HOUR in config/game.ts). Puzzle key = the SGT date (YYYY-MM-DD) on which that puzzle started, so 00:00–11:59 SGT still plays the previous date's puzzle. Weekday themes follow the puzzle key's date, not the clock.
7 prompts per day (PROMPTS_PER_DAY), 25 s timer per prompt. Days from FULL_LENGTH_FROM (config/game.ts, 2026-11-25) must have exactly 7; earlier files keep their count (the MVP days have 3), and the game plays however many prompts a puzzle file has.
Themes (config/themes.ts, a registry by weekday): Myth-busting Monday, Fishy Friday, Sunday Deep Dive (maxCR 3, bonusQuiz). Other weekdays are plain. The theme's name and tagline show on the start screen, its name on the loading screen and in the share title ("Tabimate #31 · Fishy Friday 🌲 Forest").
Biomes (config/biomes.ts): Town 0, Grassland 50, Forest 125, Rocky hills 200, Rainforest 300, Wetland 420, Snowy peak 560 (total score to enter; a 7-prompt day maxes at 700, all-EN reaches Snowy peak). Each has code-drawn placeholder art in scene/biomes/ (registry.ts; a missing one is a compile error). After each answer the result stays up until the player taps Next (or presses Enter); the next prompt's timer starts then. While the result is up, the animal joins the party in the scene and everyone walks on its points' distance; a miss leaves footprints and the party stays put.
One run per day; progress is saved and resumable.
Continuous world (scene/strip.ts, pure, tested): the journey is one strip. The player always stands at distanceFor(score) (DISTANCE_PER_POINT, config/game.ts). Each biome starts at distanceFor(minScore), and its border of BIOME_BORDER px (config/render.ts) is centred on that start: worldStateAt(x) gives { biome (the one being left), nextBiome, blend }, half way exactly at the start, so dominantBiome() (the sky, title cards, water) always equals the score's biome and the scene never disagrees with "Reached the ...". With reduced motion the blend cuts at the start (cutBlend). After runFinished the scene shows no more title cards (world.endJourney). The renderer (scene/drawScenery.ts, one scenery drawer behind a SceneryBackend: Kaplay live, 2D canvas for the results still) draws each parallax layer of the current biome at 1 - blend under the next one's at blend (the bottom ground layer stays solid), mixes the sky by blend (scene/skyMix.ts), and mixes props of both biomes inside a border by each prop's seeded roll. dominantBiome() switches at blend 0.5 (the page colour above the scene; the hook for ambience, of which there is none yet). Border art: scene/borders/registry.ts keyed "town>grassland" with optional groundTile and gateway; a missing pair just blends. Passing a gateway (the border's middle, the biome's start) shows the biome's title card (TITLE_CARD). Walks run at WALK.speed, capped at WALK.maxS. Reduced motion: no walk (the party is placed at once, a cut), no blend, no mixed props. A miss leaves footprints and the party stays put; each miss since the last hit lands FOOTPRINT_STEP further on. Drawing allocates nothing per frame: tile() and segmentsInView() write into scratch objects, and the prop cache (props.ts createPropCache) uses numeric keys and drops its oldest entry when full. A config test checks every biome gap fits a border.
Levels and scoring
Levels (LEVELS in config/levels.ts): 0 no match; 1 LC Least Concern, 2 NT Near Threatened, 3 VU Vulnerable, 4 EN Endangered, 5 CR Critically Endangered. Labels are flavour only; they do not mean real conservation status.
Every answer on every prompt has a hand-set level 1–5. Points are fixed per level: 1 = 10, 2 = 25, 3 = 50, 4 = 85, 5 = 100. Points come only from core/scoring.ts (pointsFor, dayTotal).
Exactly one level-5 (CR) answer per prompt, or 1 to the theme's maxCR (Sunday Deep Dive: up to 3). The validator reads maxCR for the puzzle's date (maxCRFor).
100 is the maximum per answer. Day multipliers (bonus quiz) apply to the day total only.
Bonus quiz (Sunday Deep Dive, the theme's bonusQuiz): public/data/bonus/{date}.json holds BONUS.questions (3) items { statement, answer: boolean, explanation (BONUS.explanationWords, 15, words or fewer) }, read by data/validateBonus.ts; the puzzle source attaches it as Puzzle.bonus on a quiz day (a missing file means no quiz). validate-data requires it for every upcoming quiz day and freezes it with its day once live (record key "date/bonus"): a live quiz that changes, is deleted, or appears after its day was recorded fails the check (scripts/lib/releaseReport.ts). An answer tapped after the deadline counts as a timeout (background tabs delay the timer). After the last prompt's reveal ("Bonus quiz" instead of "See results") the run enters status 'bonus' (core/bonus.ts, actions bonusNext and bonusAnswer; the normal flow is unchanged on other days): an intro, then each question for BONUS.questionMs (10 s) with True and False buttons, then its explanation. A timeout is wrong. Each answer stores whether it was right, so a saved run never needs the file to score. core/scoring.ts: bonusMultiplier = 1 + 0.1 per right answer (max 1.3), dayTotal(results, bonus) = round(base x multiplier); baseTotal is the answers' points alone, which decides the walk, the biome reached and the results scenery. runFinished carries base, multiplier and score; results and the share text show "Base 540 ×1.2 = 648" (bonusLine), history stores base and score, the last-biome achievement reads base. The game controller wires two runners: core/roundRunner.ts (prompts) and core/bonusRunner.ts (the quiz); ui/bonusFlow.ts and ui/screens/bonus.ts show the quiz.
Answering and matching
Only an answer's exact display name scores (after normalising case, accents, punctuation and plurals: "killer whales!" is exact for Killer whale).
On each Go the guess runs through the matcher strategies in order: exact, alias, typo, partial, loose (core/matcher/strategies.ts).
exact: scored and revealed at once.
alias, typo, partial or loose: not scored. The box is replaced with that animal's exact name (selected) and a one-line hint says "Did you mean this? Press Go to answer." Go again submits it; typing replaces it.
no match: not scored. The box keeps the text and a one-line red message says it is not on today's list. The player can retry until time runs out.
A guess naming two or more animals ("platypus tiger koala"), or more than one word longer than the name it matched, counts as no match, so pasting a list never beats naming one animal.
Time-up submits whatever is in the box: scored only if it is an exact name (e.g. a correction the player left in the box), otherwise level 0. An empty box is level 0.
Ties between equally scored candidates (one strategy, same score) go, in order, to: the display name containing the whole guess as whole words, the shorter display name, a group over a species, the lower level, then a hash (TIE_RULES and compareTies in core/matcher/pick.ts). partial returns a group whose whole name or alias is the guess, never a species that merely starts with it. The debug panel shows which rule broke a tie.
No random or lucky matching, ever. Matcher thresholds live in MATCHER_CONFIG (config/game.ts).
Content and data
Animals are group ("penguin") or species ("African penguin", parent: penguin). Groups are normal answers, usually low level, and can nest (giant salamander under salamander). A group has a representative species used for its sprite.
A family name ("hummingbird", "duck", "fox") is never a species alias: it is its own group answer, so a general guess scores the group's level, not a rarer species'.
Animal records carry traits (AnimalTraits; allowed values in config/traits.ts), a one-line description (15 words or fewer, drafted from Wikipedia, descriptionReviewed flag) and a wiki link (an en.wikipedia.org article) that is always shown beside the description. Unknown is not false: a missing trait never matches a query. core/traits.ts queryAnimals(animals, filter) answers trait and name-rule queries (equals, includes, range, kind, name rules, and/or/not) for prompt templates.
Content pipeline: scripts/input/animals.txt lists every animal (kind | display | id= wiki= parent= rep= emoji= move=). seed-traits drafts traits from Wikidata and draft-descriptions drafts descriptions from Wikipedia, into data-drafts/ only; each has --merge, which fills only empty fields of animals.json and never overwrites. New animals take their emoji, movement, tint and archetype from their parent group, else their class. Both scripts throttle to 1 request/s, retry on 429, cache in data-drafts/cache/ (not committed) and send a generic User-Agent (TABIMATE_CONTACT adds contact details).
The validator (data/validate.ts, data/checkHierarchy.ts) enforces: levels 1–5, the CR rule with the day's maxCR (from LEVEL_RULES_FROM), exactly PROMPTS_PER_DAY prompts (from FULL_LENGTH_FROM), parents that exist and are groups (no loops), each group's representative a species below it, no animal twice on a prompt. validate-data (data/checkNames.ts) also fails when an answer's display name does not score exactly on its own prompts, or an alias resolves to another answer (so a correction always leads to a score). A species ranked below its own group on a prompt is only a warning (validate-data prints it).
Released puzzles are frozen: a player's stored levels must keep matching the file. Puzzles before LEVEL_RULES_FROM (config/game.ts, 2026-11-19) keep their v1 answers and levels and are only checked for shape. validate-data fails when a day that has gone live differs from scripts/released-puzzles.json. The workflow's record job adds each new live day at 12:05 SGT and commits it; validate-data fails if a live day before today is still unrecorded (the job fell behind; run npm run validate-data -- --record and commit). Fix a released day by changing a future one.
Saves: SCHEMA_VERSION 5 (services/saveData.ts; migrations in services/migrations.ts). Migration 1 renamed match.tier to match.level and history tiers to levels. Migration 2 added the journal (back-filled from the finished runs still saved: history keeps only levels, not animals) and achievements (empty; they unlock on the next finished run, which checks the whole history). Migration 3 named each history day's animals (animalIds, back-filled from the runs still saved; older days keep levels only) and added streak freezes (freezes, frozenKeys). Migration 4 added the bonus quiz: runs gain bonusCount 0, bonusResults [] and bonusEndsAt null; history entries gain base (= score). Migrations that check runs (2, 3) fill those bonus defaults first, or old runs would fail the current guard and be lost. Any change to saved data needs a version bump and a migration.

Sprite pipeline: public/assets/sprites/{archetype}.png + .json (Aseprite export, frame tags walk and flap or swim), listed in manifest.json, drawn only in TEMPLATE_KEYS (config/render.ts). animals.json gives each animal palette, shinyPalette and paletteOverride; palette colours come from data/master-palette.json (tested). An animal without a sheet or palette is drawn as its emoji. SPRITE_SOURCE picks the provider. A group has no art of its own: the pixel provider draws it with its representative's sheet (core/hierarchy.ts representativeFor) in plainer colours: palettes.json's "<palette>-plain" if it exists, else the representative's palette desaturated (PLAIN_PALETTE in config/sprites.ts; outline and eyes kept; its shiny stays as designed). Placeholders: npm run art:placeholders (scripts/drawPlaceholderSheets.ts) draws a sheet for every archetype in animals.json from a body plan registry (scripts/lib/placeholder/plans.ts; archetypes.ts gives each archetype its plan and look; a test checks every archetype has one and every frame fits), with walk always, flap if any of its animals fly and swim if any swim. It redraws only sheets whose meta.app is its own (an Aseprite export of the same name replaces a placeholder for good), removes placeholders no archetype uses, and gives every animal that draws itself and has no palette one made from its tint (DERIVED_PALETTE), never changing existing palettes. Movement (scene/entities/movement.ts, a registry by animal.movement; sizes in config/movement.ts): land walks on the trail; sky hovers SKY.hoverPx above it with a sine bob and a ground shadow, playing the sheet's 'flap' tag (else its walk); water rides a bubble on land and swims (sunk a little, the 'swim' tag) in WATER.swimBiomes (Wetland, by the dominant biome); the bubble pops over WATER.popMs and forms again on land. Architecture rules (must follow)
Layers: config, core, data, services, ui, scene, plus functions/ for server code. main.ts wires the client together.
core/ is pure TypeScript: no DOM, no Kaplay, no fetch, no localStorage, no Date.now() without injection. It is fully unit-tested.
ui/ and scene/ never call each other. They both react to events from core/events.ts and send user intents back to the game machine.
External dependencies sit behind interfaces: PuzzleSource, StorageAdapter, SpriteProvider, Clock, StatsSource (core/stats.ts), and later AccountSource. The interfaces live in core/ (so the game machine can use them); implementations live in data/, services/ or scene/. main.ts chooses them. Anything that talks to a server also has a local implementation, so the game still works offline and as a guest.
functions/ imports only pure code from src/ (config/ and core/: types, dates, the stats config) and its own functions/lib/; never ui/, scene/, services/, data/, dev/ or wiring/ (an eslint rule).
Tuneable values live in config/, never as magic numbers in logic.
Features hook in through registries: adding one means adding an entry, not editing a switch statement. Existing: biomes, levels, effects, matcher strategies, themes, reveal extras, biome borders (scene/borders/), journal sets, achievements. Planned: prompt templates, movement strategies.
Code style
Small files (aim < 150 lines) and small functions (aim < 30 lines), one job each.
Named exports only. No default exports. No any.
Pure functions where possible; side effects at the edges.
Every exported function in core/ has a unit test.
Comments explain why, not what.
Mobile first: must work at 360 px wide with the on-screen keyboard open.

## v3 decisions

- Database: every animal class with an English common name, built offline into db/
  (generated taxa.jsonl.gz, trait-rules.json, curated.json). Curated edits always win.
  Players never download the whole database.
- Popularity = Wikidata sitelink count (number of Wikipedias with an article), refined by
  Wikipedia pageviews where fetched. It drives default levels and art priority.
- Scientific names are accepted as aliases and corrected to the common name.
- Prompts are rules over the database plus include, exclude, level overrides and a
  hand-picked CR. Default levels by popularity rank within the prompt: LC groups + top 3%,
  NT next 12%, VU next 35%, EN last 50% (config). A species is at least one level above
  its group on the same prompt.
- Compiled day bundles (public/data/days/{date}.json) are what the game loads. Released
  bundles are frozen and committed; the database can never change a past day.
- Encounters after prompts in ENCOUNTER_AFTER (default [3, 5, 7]): 4 choices, 10 s,
  +0.1 multiplier each, max x1.3. Befriended animals go to the Journal only.
- Level badges stay LC..CR on every prompt, conservation prompts included; they describe
  how rare the answer is, not the animal's real status.
- Wide screens: the scene is framed, not stretched.
- Performance budgets: first JS under 60 KB gzipped; start screen under 1.5 s and first
  prompt under 3 s on a first visit (mid phone, 4G); repeat visits under 1 s.
