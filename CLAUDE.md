Tabimate — project brief
What it is

Tabimate (旅 tabi = journey + mate) is a daily browser trivia game about animals. Everyone gets the same prompts each day (e.g. "Name an animal that lays eggs"). The player types an animal; each accepted answer has a hand-set level (1–5, 0 for no match). Each matched animal joins a trail of followers behind the player. Each answer moves the player forward by its level; crossing score thresholds enters new biomes (Town → Grassland → Forest → …). The run ends with a shareable team card. Original art and naming only: no Pokémon names, sprites or UI.

Rules of the game
Daily reset at 12:00 (noon) Asia/Singapore (RESET_HOUR in config/game.ts). Puzzle key = the SGT date (YYYY-MM-DD) on which that puzzle started, so 00:00–11:59 SGT still plays the previous date's puzzle. Weekday themes follow the puzzle key's date, not the clock.
7 prompts per day (PROMPTS_PER_DAY), 25 s timer per prompt. Days from FULL_LENGTH_FROM (config/game.ts, 2026-11-25) must have exactly 7; earlier files keep their count (the MVP days have 3), and the game plays however many prompts a puzzle file has.
Themes (config/themes.ts, a registry by weekday): Myth-busting Monday, Fishy Friday, Sunday Deep Dive (maxCR 3, bonusQuiz). Other weekdays are plain. The theme's name and tagline show on the start screen, its name on the loading screen and in the share title ("Tabimate #31 · Fishy Friday 🌲 Forest").
Biomes (config/biomes.ts): Town 0, Grassland 50, Forest 125, Rocky hills 200, Rainforest 300, Wetland 420, Snowy peak 560 (total score to enter; a 7-prompt day maxes at 700, all-EN reaches Snowy peak). Each has code-drawn placeholder art in scene/biomes/ (registry.ts; a missing one is a compile error). After each answer the result stays up until the player taps Next (or presses Enter); the next prompt's timer starts then. While the result is up, the animal joins the party in the scene and everyone walks on its points' distance; a miss leaves footprints and the party stays put.
One run per day; progress is saved and resumable.
Continuous world (scene/strip.ts, pure, tested): the journey is one strip. The player always stands at distanceFor(score) (DISTANCE_PER_POINT, config/game.ts), so the strip's biome always equals the score's. Each biome starts at distanceFor(minScore); the BIOME_BORDER px (config/render.ts) before it blend: worldStateAt(x) gives { biome, nextBiome, blend }. The renderer (scene/drawScenery.ts, one scenery drawer behind a SceneryBackend: Kaplay live, 2D canvas for the results still) draws each parallax layer of the current biome at 1 - blend under the next one's at blend (the bottom ground layer stays solid), mixes the sky by blend (scene/skyMix.ts), and mixes props of both biomes inside a border by each prop's seeded roll. dominantBiome() switches at blend 0.5 (the page colour above the scene; the hook for ambience, of which there is none yet). Border art: scene/borders/registry.ts keyed "town>grassland" with optional groundTile and gateway; a missing pair just blends. Passing a gateway (the border's middle) shows the biome's title card (TITLE_CARD). Walks run at WALK.speed, capped at WALK.maxS. Reduced motion: no walk (the party is placed at once, a cut), no blend, no mixed props. A miss leaves footprints and the party stays put; each miss since the last hit lands FOOTPRINT_STEP further on. Drawing allocates nothing per frame: tile() and segmentsInView() write into scratch objects, and the prop cache (props.ts createPropCache) uses numeric keys and drops its oldest entry when full. A config test checks every biome gap fits a border.
Levels and scoring
Levels (LEVELS in config/levels.ts): 0 no match; 1 LC Least Concern, 2 NT Near Threatened, 3 VU Vulnerable, 4 EN Endangered, 5 CR Critically Endangered. Labels are flavour only; they do not mean real conservation status.
Every answer on every prompt has a hand-set level 1–5. Points are fixed per level: 1 = 10, 2 = 25, 3 = 50, 4 = 85, 5 = 100. Points come only from core/scoring.ts (pointsFor, dayTotal).
Exactly one level-5 (CR) answer per prompt, or 1 to the theme's maxCR (Sunday Deep Dive: up to 3). The validator reads maxCR for the puzzle's date (maxCRFor).
100 is the maximum per answer. Day multipliers (bonus quiz) apply to the day total only.
Bonus quiz (Sunday Deep Dive, the theme's bonusQuiz): public/data/bonus/{date}.json holds BONUS.questions (3) items { statement, answer: boolean, explanation (BONUS.explanationWords, 15, words or fewer) }, read by data/validateBonus.ts; the puzzle source attaches it as Puzzle.bonus on a quiz day (a missing file means no quiz). validate-data requires it for every upcoming quiz day and freezes it with its day once live (record key "date/bonus"): a live quiz that changes, is deleted, or appears after its day was recorded fails the check (scripts/lib/releaseReport.ts). An answer tapped after the deadline counts as a timeout (background tabs delay the timer). After the last prompt's reveal ("Bonus quiz" instead of "See results") the run enters status 'bonus' (core/bonus.ts, actions bonusNext and bonusAnswer; the normal flow is unchanged on other days): an intro, then each question for BONUS.questionMs (10 s) with True and False buttons, then its explanation. A timeout is wrong. Each answer stores whether it was right, so a saved run never needs the file to score. core/scoring.ts: bonusMultiplier = 1 + 0.1 per right answer (max 1.3), dayTotal(results, bonus) = round(base x multiplier); baseTotal is the answers' points alone, which decides the walk, the biome reached and the results scenery. runFinished carries base, multiplier and score; results and the share text show "Base 540 ×1.2 = 648" (bonusLine), history stores base and score, the last-biome achievement reads base. The game controller wires two runners: core/roundRunner.ts (prompts) and core/bonusRunner.ts (the quiz); ui/bonusFlow.ts and ui/screens/bonus.ts show the quiz.
Answering and matching
Only an answer's exact display name scores (after normalising case, accents, punctuation and plurals: "killer whales!" is exact for Killer whale).
On each Go the guess runs through the matcher strategies in order: exact, alias, typo, partial, loose (core/matcher/strategies.ts).
exact: scored and revealed at once.
alias, typo, partial or loose: not scored. The box is replaced with that animal's exact name (selected) and a one-line hint says "Did you mean this? Press Go to answer." Go again submits it; typing replaces it.
no match: not scored. The box keeps the text and a one-line red message says it is not on today's list. The player can retry until time runs out.
A guess naming two or more animals ("platypus tiger koala"), or more than one word longer than the name it matched, counts as no match, so pasting a list never beats naming one animal.
Time-up submits whatever is in the box: scored only if it is an exact name (e.g. a correction the player left in the box), otherwise level 0. An empty box is level 0.
Ties between equally scored candidates (one strategy, same score) go, in order, to: the display name containing the whole guess as whole words, the shorter display name, a group over a species, the lower level, then a hash (TIE_RULES and compareTies in core/matcher/pick.ts). partial returns a group whose whole name or alias is the guess, never a species that merely starts with it. The debug panel shows which rule broke a tie.
No random or lucky matching, ever. Matcher thresholds live in MATCHER_CONFIG (config/game.ts).
Content and data
Animals are group ("penguin") or species ("African penguin", parent: penguin). Groups are normal answers, usually low level, and can nest (giant salamander under salamander). A group has a representative species used for its sprite.
A family name ("hummingbird", "duck", "fox") is never a species alias: it is its own group answer, so a general guess scores the group's level, not a rarer species'.
Animal records carry traits (AnimalTraits; allowed values in config/traits.ts), a one-line description (15 words or fewer, drafted from Wikipedia, descriptionReviewed flag) and a wiki link (an en.wikipedia.org article) that is always shown beside the description. Unknown is not false: a missing trait never matches a query. core/traits.ts queryAnimals(animals, filter) answers trait and name-rule queries (equals, includes, range, kind, name rules, and/or/not) for prompt templates.
Content pipeline: scripts/input/animals.txt lists every animal (kind | display | id= wiki= parent= rep= emoji= move=). seed-traits drafts traits from Wikidata and draft-descriptions drafts descriptions from Wikipedia, into data-drafts/ only; each has --merge, which fills only empty fields of animals.json and never overwrites. New animals take their emoji, movement, tint and archetype from their parent group, else their class. Both scripts throttle to 1 request/s, retry on 429, cache in data-drafts/cache/ (not committed) and send a generic User-Agent (TABIMATE_CONTACT adds contact details).
The validator (data/validate.ts, data/checkHierarchy.ts) enforces: levels 1–5, the CR rule with the day's maxCR (from LEVEL_RULES_FROM), exactly PROMPTS_PER_DAY prompts (from FULL_LENGTH_FROM), parents that exist and are groups (no loops), each group's representative a species below it, no animal twice on a prompt. validate-data (data/checkNames.ts) also fails when an answer's display name does not score exactly on its own prompts, or an alias resolves to another answer (so a correction always leads to a score). A species ranked below its own group on a prompt is only a warning (validate-data prints it).
Released puzzles are frozen: a player's stored levels must keep matching the file. Puzzles before LEVEL_RULES_FROM (config/game.ts, 2026-11-19) keep their v1 answers and levels and are only checked for shape. validate-data fails when a day that has gone live differs from scripts/released-puzzles.json. The workflow's record job adds each new live day at 12:05 SGT and commits it; validate-data fails if a live day before today is still unrecorded (the job fell behind; run npm run validate-data -- --record and commit). Fix a released day by changing a future one.
Saves: SCHEMA_VERSION 5 (services/saveData.ts; migrations in services/migrations.ts). Migration 1 renamed match.tier to match.level and history tiers to levels. Migration 2 added the journal (back-filled from the finished runs still saved: history keeps only levels, not animals) and achievements (empty; they unlock on the next finished run, which checks the whole history). Migration 3 named each history day's animals (animalIds, back-filled from the runs still saved; older days keep levels only) and added streak freezes (freezes, frozenKeys). Migration 4 added the bonus quiz: runs gain bonusCount 0, bonusResults [] and bonusEndsAt null; history entries gain base (= score). Migrations that check runs (2, 3) fill those bonus defaults first, or old runs would fail the current guard and be lost. Any change to saved data needs a version bump and a migration.
Tech

Vitest for tests. ESLint + Prettier.

GET ?date= gives players per prompt and answer, cached STATS.cacheSeconds (60 s). Table runs in migrations/0001_runs.sql. The results ask for the day's stats after the run is sent; a prompt with STATS.minPlayers (20) or more players shows "x% picked this" under the player's answer and a share beside every answer in its list (core/stats.ts pickedShare; teamCard showShares); fewer, offline or an error: no percentages. Levels and points stay hand-set. Configured in config/stats.ts. wrangler.toml is for local work and migrations only (no pages_build_output_dir: the Pages dashboard keeps the production DB binding); its database_id is a placeholder until the real one is filled in.
Pixel art: scene is 180 native px tall, scaled by a whole number (computed in device pixels); layers tile horizontally. Sprites use 6 template key colours, recoloured from palettes.json.
Reveal and effects: the reveal card plays a drum-roll (longer for higher levels), the level badge popping in, then the name (REVEAL_TIMING in config/game.ts); the points count up as the name shows. The card shows the animal's sprite walking (shiny at the shiny level; its emoji until the sprite is ready or where there is none). Under the name, reveal extras (ui/reveal/extras.ts, a registry, in order): jackpot (a gold "Jackpot find!" banner at the top level), factLine (the animal's description), nearMiss (for a group answer, the rarest species under it on this prompt that beats it, never the CR answer). The jackpot moment: a top-level find freezes after its badge (jackpotFreezeMs), then flashes gold with its own sound as the shiny follower joins. revealNameMs() is the one source for when the name shows and the animal joins: the reveal, audio and scene all use it. Each level's effect (LEVELS[].effectId: none, glint, sparkle, shiny) has a scene effect in scene/effects/ (entrance when the animal joins, then a subtle idle loop) and a badge style in reveal.css. Reduced motion: no shake or particles, only fades.
Results page: on phones too, the card floats over the full-window scene of the biome reached. The party line-up (traveller in front, animals behind) walks on the spot in a framed snapshot of the scenery where the run ended (Scene.backdrops(score), painted with the scene's own strip so it matches the walk; emoji and plain colours without a scene). The card has room above its title and scrolls within the viewport on small screens. Team rows (components/teamCard.ts, compact type) show the sprite or emoji in a fixed 48 px slot (so text lines up across rows), "Q3 · the full prompt" (wrapping) over the answer, and "VU · 50" in its own column at the right, centred against both. No "group" tags anywhere. A row opens to its answer list (components/answerList.ts, built on first open): a labelled region headed "142 possible answers", a search box past RESULTS_LIST.searchFrom answers, and a 220 px scroll box of small rows (names and scores bold), rarest first, each tinted a light version of its level's colour (white, blue, red, purple, gold; --answer-tint from LEVELS), the player's answer marked with an accent bar and a visible "(your answer)" tag and scrolled into view. Each answer (answerRow.ts) opens to its description, right under the name, and a "Read more on Wikipedia" link (new tab). Arrow keys, Home and End move between rows; rows render RESULTS_LIST.renderWindow at a time.
Field Journal and achievements: every animal found is kept forever. On runFinished, main.ts calls progress.completeRun(state, animals), which in one write records the day (streak, history), adds its finds to the journal (core/journal/journal.ts addRun: firstFoundKey, timesFound, bestLevel) and unlocks achievements (core/achievements/registry.ts, a registry; evaluate returns only new ids), all only the first time the day is recorded, so a reload never counts a run twice. Then it emits journalUpdated and achievementUnlocked (core/collectionEvents.ts). Sets (core/journal/sets.ts, a registry) are species only, chosen by a group (under('bear')), several (either(under('whale'), under('dolphin'))), one id (is('chimpanzee')) or a core/traits.ts filter (ofClass('amphibian')): bears, big cats, penguins, sharks, whales and dolphins, seals and sea cows, elephants, apes and monkeys, rabbits and hares, deer and antelope, birds of prey, owls, parrots, reptiles, amphibians, fish, insects and spiders, Australia and Oceania, flightless birds; setProgress gives found/total. Goals (streaks, journal sizes, the perfect-day level) and TOAST timing live in config/collection.ts. Achievement checks read the whole record (best streak, history, journal), so one earned before it existed unlocks on the next run. UI (ui/collectionUi.ts): the Journal screen (ui/screens/journal.ts, from the start and results screens) has tabs for all animals, each set (progress, a "Complete!" stamp) and achievements; each cell shows its picture with the name in small type under it; found animals are buttons opening their page (name, best level, description, wiki link, first found, times found), unfound ones are dark silhouettes named "???". Its pictures are pixel sprites for any animal (scene/sprites/stillPortraits.ts: recoloured on first ask without the scene, which has only today's sprites; wired by wiring/startScene.ts journalPortraits), emoji where there is none. The title, count and Back share one header row; the selected tab scrolls into view. A chosen animal's page is a compact popup (never capped or scrolled: small type and a 64 px moving animal keep it about a quarter of a phone screen; sticky over the top of the grid; a corner × closes it; the Wikipedia link and the first-found line share one line) with the animal moving on the left: its sheet's walk, flap or swim by movement (an emoji hops); its cell is outlined. On a phone (max-width 767px or max-height 520px) the journal is a card over the full-window scene like the results (html.is-journal, base.css), as wide as the results card and 90% of the screen tall, with only its panel scrolling and compact tab chips (journalPhone.css). The tabs use a roving tabindex (Left, Right, Home, End). The journal total and journal-N goals count every answer found, groups included ("penguin" is its own cell); sets count species only. Full house and Perfect day count each day's own prompts (its history levels), not PROMPTS_PER_DAY. Renaming or merging an animal id needs a save migration (see SCHEMA_VERSION). Toasts (components/toaster.ts, in the host's toast layer) queue one at a time. A reveal of an animal in neither the journal nor earlier answers today shows "New to your journal!" (reveal extra newFind).
Streaks and history: one streak freeze is earned each time the streak reaches a multiple of STREAK_FREEZE.earnEvery (7) days, holding at most maxHeld (1). A single missed day spends it automatically on the next finish (core/streak.ts recordRun; the covered day goes in frozenKeys); streakStatus(stats, today) keeps the streak alive meanwhile and the start screen says "Streak saved by a freeze" (or "Freeze ready" while one is held). Two missed days lose the streak and keep the freeze. The History screen (ui/screens/history.ts, from the start and results screens) is a Monday-first month calendar (core/calendar.ts) from the first month played to now: played days coloured by score band (SCORE_BANDS, config/history.ts; --band-N tokens), freeze-covered days marked ❄, a tap shows the day's score, band, biome and team (local history only). The results show tomorrow's theme name only (never its prompts). The install hint ("Install Tabimate", services/install.ts + components/installHint.ts) shows on the start and results screens once INSTALL_HINT.afterDays (3) days are finished, until dismissed (kept in storage) or installed; it opens the browser's install dialog where there is one (beforeinstallprompt, caught at load), else explains the Share-menu route (iOS).
PWA: vite-plugin-pwa (vite.config.ts) writes the manifest (standalone, icons in public/icons/ from npx tsx scripts/make-icons.ts) and a service worker that precaches the app shell and art (js, css, html, sprites, icons; not data/) and is network-first for /data/*.json (puzzles and animals: fresh online, last copy offline). Fonts are cached on first use.
Sharing: services/share.ts builds the share text (title, level squares, animal emoji, the site link; never animal names or prompts) from shareCard(), plain data an image card can reuse. Phones get the share sheet, desktops copy to the clipboard. The share image (services/shareImage.ts, layout in shareImageLayout.ts, sizes in config/ui.ts SHARE_IMAGE) is a 1080x1350 PNG: title and theme, date, score, biome, the scene where the run ended (the results backdrop), and each prompt's animal (sprite or emoji) with its level badge, never names or prompts. wiring/startShare.ts makes it once as the results open; Share attaches it as a file where navigator.canShare allows (else the text alone), and "Save image" downloads it.
Sound: services/audio.ts is the only thing that plays audio, driven by bus events. Sounds are synthesised (services/sounds.ts), unlocked on the first tap or key, and muted with the corner button (kept via StorageAdapter). Haptics (services/haptics.ts): a navigator.vibrate pattern per level (LEVELS[].vibration) as the badge lands, behind feature detection, silent while muted (the same switch), driven by the bus.
Loading screen (ui/screens/loading.ts, ui/loadingFlow.ts): shown at once with the puzzle number and theme (from the date); the traveller walks a path that is the progress bar with a random animal behind, and a "Did you know?" line from descriptions once the animals load. Meanwhile the scene preloads sprites for today's animals only (core/puzzleAnimals.ts: answers plus group representatives). It stays up at least LOADING.minMs (300 ms), waits for sprites at most LOADING.spriteWaitMs, and no longer than needed; then the start screen or a restored round replaces it.
Sprite pipeline: public/assets/sprites/{archetype}.png + .json (Aseprite export, frame tags walk and flap or swim), listed in manifest.json, drawn only in TEMPLATE_KEYS (config/render.ts). animals.json gives each animal palette, shinyPalette and paletteOverride; palette colours come from data/master-palette.json (tested). An animal without a sheet or palette is drawn as its emoji. SPRITE_SOURCE picks the provider. A group has no art of its own: the pixel provider draws it with its representative's sheet (core/hierarchy.ts representativeFor) in plainer colours: palettes.json's "<palette>-plain" if it exists, else the representative's palette desaturated (PLAIN_PALETTE in config/sprites.ts; outline and eyes kept; its shiny stays as designed). In development the provider warns which animals it draws as emoji, by archetype. Placeholders: npm run art:placeholders (scripts/drawPlaceholderSheets.ts) draws a sheet for every archetype in animals.json from a body plan registry (scripts/lib/placeholder/plans.ts; archetypes.ts gives each archetype its plan and look; a test checks every archetype has one and every frame fits), with walk always, flap if any of its animals fly and swim if any swim. It redraws only sheets whose meta.app is its own (an Aseprite export of the same name replaces a placeholder for good), removes placeholders no archetype uses, and gives every animal that draws itself and has no palette one made from its tint (DERIVED_PALETTE), never changing existing palettes. Art direction and each species' look: art/README.md (sprites are cute, and every species has something of its own). npm run sprite-coverage (scripts/lib/spriteCoverage.ts) is the art to-do list (placeholders don't count as art; they show as "plchd"): every answer on every puzzle counted under the archetype that draws it, today and upcoming days counting 1 and older days halving every COVERAGE.halfLifeDays, with the top 20 archetypes that have no sheet (--all lists every one).
Movement (scene/entities/movement.ts, a registry by animal.movement; sizes in config/movement.ts): land walks on the trail; sky hovers SKY.hoverPx above it with a sine bob and a ground shadow, playing the sheet's 'flap' tag (else its walk); water rides a bubble on land and swims (sunk a little, the 'swim' tag) in WATER.swimBiomes (Wetland, by the dominant biome); the bubble pops over WATER.popMs and forms again on land. Off-ground followers don't take steps; each has its own clock and phase for bobbing; reduced motion holds them steady. scene/movementDecor.ts draws the shadow and bubble.
Architecture rules (must follow)
Layers: config, core, data, services, ui, scene, plus functions/ for server code. main.ts wires the client together.
core/ is pure TypeScript: no DOM, no Kaplay, no fetch, no localStorage, no Date.now() without injection. It is fully unit-tested.
ui/ and scene/ never call each other. They both react to events from core/events.ts and send user intents back to the game machine.
External dependencies sit behind interfaces: PuzzleSource, StorageAdapter, SpriteProvider, Clock, StatsSource (core/stats.ts), and later AccountSource. The interfaces live in core/ (so the game machine can use them); implementations live in data/, services/ or scene/. main.ts chooses them. Anything that talks to a server also has a local implementation, so the game still works offline and as a guest.
functions/ shares types from src/core/types.ts and its own functions/lib/; it never imports from ui/ or scene/.
Tuneable values live in config/, never as magic numbers in logic.
Features hook in through registries: adding one means adding an entry, not editing a switch statement. Existing: biomes, levels, effects, matcher strategies, themes, reveal extras, biome borders (scene/borders/), journal sets, achievements. Planned: prompt templates, movement strategies.
Code style
Small files (aim < 150 lines) and small functions (aim < 30 lines), one job each.
Named exports only. No default exports. No any.
Pure functions where possible; side effects at the edges.
Every exported function in core/ has a unit test.
Comments explain why, not what.
Mobile first: must work at 360 px wide with the on-screen keyboard open.

npm run seed-traits [-- --merge], npm run draft-descriptions [-- --merge]: draft traits and descriptions into data-drafts/, then merge into empty fields of animals.json. npm run content-report [-- --list]: traits missing per field, descriptions missing or unreviewed.
